# 第一版演示流程

## 1. 启动服务

```powershell
.\dev.ps1 up
```

打开：

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/docs`

## 2. 准备数据库

如果是首次启动，先执行：

```powershell
.\.venv\Scripts\python.exe scripts\migrate_db.py
```

## 3. 新增数据源

在当前版本里，建议把“手工新增数据源”作为备选方案，不再作为主演示路径。优先演示“自然语言 -> 官方入口目录/站内找源智能体 -> 采集”。

如果需要手工补录，可在“数据源管理”页面：

1. 输入名称、基础域名、站点类型、抓取模式
2. 点击“载入模板”
3. 把模板中的 `institution`、`department`、`aliases`、`list_pages` 和选择器替换成真实站点规则
4. 点击“保存数据源”

## 4. 演示站内找源智能体

在“自然语言工作台”页面：

1. 输入自然语言需求
2. 可选填写高校官网首页或研招入口 URL；不填时系统会自动使用官方入口目录
3. 点击“发现/采集 C9 研招公告”
4. 观察结果面板中的：
   - `workflow_steps`
   - `candidate_rankings`
   - `agent_trace`
   - `failure_reason`
   - `bootstrap_strategy`
   - `entrypoint_url`
   - `health_status`
5. 重点说明候选会被分成：
   - 已自动保存
   - 建议人工确认
   - 未通过校验

推荐示例：

- `提供C9高校研究生招生公告的真实数据源`
- `采集清华大学研究生招生公告`
- `提供北京大学研究生招生公告的真实数据源`

非 C9 泛化演示：

1. 输入 `采集安徽工业大学研究生招生公告`
2. 同时填写该校官方首页或研究生招生入口 URL
3. 说明系统不会开放式猜官网，而是只在用户提供的官方入口同域内做站内找源、候选校验和 source 保存

可选拒绝演示：

- `采集北京物资学院研究生招生公告的数据源`，且不填写官方入口 URL
- `采集清华大学本科招生公告的数据源`

## 5. 触发采集

如果自然语言结果里已经出现可采集的数据源：

1. 点击“采集这个数据源”
2. 观察任务详情中的进度、阶段和执行结果
3. 对比候选类型与最终入库 source，强调系统不会把 detail page 直接当长期 source
4. 如有已保存 source，可强调热启动会优先复用健康 source；失效后才触发 rediscovery

## 6. 查看结构化结果

在“文档中心”页面：

1. 用关键词、来源、类型和日期筛选
2. 点击“查看”
3. 中间面板看结构化字段
4. 右侧面板看原始文本和 LLM 日志

## 7. 测试自然语言链路

在“自然语言工作台”页面：

- `仅解析`：检查意图、时间范围、数据源匹配是否正确
- `解析并执行`：直接发起受控选源 / 采集
- `查询已采集结果`：对已有文档做问答或总结

推荐示例：

- `采集清华大学研究生招生公告`
- `提供C9高校研究生招生公告的真实数据源`
- `最近有哪些研究生招生复试信息？`

## 8. 结束演示

```powershell
.\dev.ps1 down
```
