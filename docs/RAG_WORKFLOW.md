# RAG 闭环说明

当前演示版把研究生招生公告采集和证据型问答串成一个闭环。C9 高校可通过官方入口目录冷启动；非 C9 高校需要用户提供官方首页或研究生招生入口 URL 后进入受控站内发现。

`自然语言采集请求 -> 官方入口目录/健康 Source 复用 -> 站内找源/校验 -> 受控采集 -> 结构化抽取 -> 读取入库文档 -> 生成带引用答案`

在 mock/CI 演示环境中，`/api/v1/nl/execute` 会同步跑完整链路并立即返回引用答案。  
在真实高校站点环境中，为避免页面慢加载导致接口超时，`/api/v1/nl/execute` 会快速返回采集任务；任务完成后，再通过“查询已采集数据”或 `/api/v1/ask` 读取新文档生成引用答案。

## 触发方式

自然语言入口直接输入：

```text
采集复旦大学的研究生招生公告
采集清华大学研究生招生公告
采集安徽工业大学研究生招生公告（同时提供官方入口 URL）
```

系统会在 `/api/v1/nl/execute` 响应中返回：

- `task_ids`：本次采集任务 ID
- `documents`：本次可用于问答的结构化文档
- `answer`：基于已采集文档生成的回答
- `citations`：引用证据，包含文档 ID、原始页面 ID、数据源 ID、标题、来源 URL、证据字段、片段和证据哈希
- `retrieved_documents`：RAG 召回文档及分数
- `confidence_notes`：回答置信说明

如果是真实站点后台采集，首次响应中的 `documents` / `citations` 可能为空；此时先查看 `task_ids` 对应任务状态，任务成功后再查询：

```text
最近有哪些复旦大学研究生招生公告？
```

## 设计边界

- 回答只基于本地已采集文档，不凭空补充。
- 如果本次采集没有得到文档，或候选文档相关度低于最低阈值，系统会明确返回“未找到足够证据”，不会为了生成引用而回退到任意文档。
- 采集前会优先复用健康 source；source 失效时才重新进入站内发现。
- 非 C9 高校必须显式提供官方入口 URL，系统不会让模型开放式猜测官网。
- 当前 RAG 是轻量关键词召回，适合本地 MVP 演示；后续可替换为向量检索，但不影响 API 字段。

## Citation 校验

离线评测会检查每条 Citation 的 `document_id`、`source_url`、`evidence_field` 和 `snippet` 是否能共同回到同一条已采集文档。`evidence_hash` 用于发现证据内容在后续处理过程中是否发生变化，但不替代原文 URL 和原始页面存档。
